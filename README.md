# M.I.M.I.C（軽音部 引き継ぎアシスタント）

部の資料（PDF・画像・テキスト）を読ませて、引き継ぎについて何でも質問できるアプリ。
質問に答えるAIは Gemma 4 26B A4B、資料の文字起こしと検索の準備は Gemini（どれも Google の無料枠）。
資料が多いときは、質問に関係しそうな部分だけを探して（RAG）AIに渡すので、資料が増えても速い。

---

## 使う人向け

### インストール

1. `MIMIC-Setup.exe` をダブルクリック →「次へ」で進める（管理者権限は不要）
   - 「WindowsによってPCが保護されました」と出たら「詳細情報」→「実行」
2. デスクトップの **M.I.M.I.C** アイコンをダブルクリック
3. 初回だけ APIキーの設定画面が出るので、画面の手順どおりに Google AI Studio でキーを作って貼り付ける

閉じるときはウィンドウの × でOK（裏の処理も1分ほどで自動で終わる）。

### 使い方

- 下の入力欄に質問を書いて送るだけ。答えの最後に【出典】が出る
- 「覚えて：〇〇」と送ると、その内容を記憶する
- 左上の「メニュー」から：会話のリセット、資料の追加・削除、APIキーの変更、機能説明
- 新しいバージョンが出ると、起動したときに自動で更新される（資料・記憶・APIキーはそのまま）
- 更新後に調子が悪いときは、メニューの「設定」→「前のバージョンに戻す」

### 資料を追加する

メニューの「資料」から、どちらかの方法で。

- **ファイルを選ぶ**：PDF・画像・テキストを選ぶ（ドラッグでもOK）→「読み込む」
- **フォルダに入れる**：「docsフォルダを開く」→ 開いたフォルダにファイルを入れる →「未読込の資料を読み込む」

Word・Excel は PDF にしてから。1ファイル18MBまで、長いPDF（目安30ページ以上）は分割したほうが確実。

## 管理する人向け

### フォルダの中身

| ファイル | 役割 |
| --- | --- |
| `app.py` | アプリ本体（名前・あいさつ・AIモデル・口調はファイルの上のほう） |
| `convert.py` | 資料の文字起こし（`MODEL` は Gemini） |
| `launcher.py` | デスクトップのアイコンから起動する仕組み |
| `search.py` | 資料の検索（資料が多いとき、質問に関係する部分だけを探してAIに渡す） |
| `updater.py` / `version.txt` | 自動アップデートの仕組み / 今のバージョン |
| `style.css` / `logo.png` / `mimic.ico` | 見た目・ロゴ・アイコン |
| `docs/` | 元の資料 |
| `texts/` | 文字起こしした資料と「チャットで覚えた情報.txt」 |
| `.env` | APIキー（人に渡さない） |
| `installer/` | インストーラーを作る道具（`build.bat`）とアップデートを配る道具（`release.bat`） |

### インストーラーを作る（Windows）

1. 最初に一度だけ、[Inno Setup](https://jrsoftware.org/isdl.php) をインストール
2. `installer` フォルダの `build.bat` をダブルクリック（初回は数分かかる。ネット接続が必要）
3. `installer\dist\MIMIC-Setup.exe` ができる → これを配る

- そのとき `texts` にある資料と記憶が同梱される。このPCにインストール済みの M.I.M.I.C で追加した資料も、新しいほうが自動で入る
- 元のPDFなども一緒に配りたいときは、`installer` フォルダでターミナルを開いて `build.bat -IncludeDocs`
- APIキー（`.env`）は同梱されない。使う人がそれぞれ自分のキーを設定する
- 新しい版を作り直して配り直しても、相手のPCにある資料・記憶は消えない（同じ名前のファイルは上書きしない）

### GitHub でインストーラーを配る

GitHub の Releases に置くと、`https://github.com/ユーザー名/リポジトリ名/releases/latest` を教えるだけで、誰でも最新版をダウンロードできる。
**公開すると誰でもダウンロードできる**ので、部の資料・記憶は入れない版（`-NoData`）を置く。資料は別の方法で渡す。

1. `installer` フォルダでターミナルを開き、`build.bat -NoData` を実行（公開用インストーラーができる）
2. `release.bat` を実行 → インストーラーとアップデート用 zip が同じリリースにまとめて公開される
3. 上の `releases/latest` のリンクを部員に送る

### アップデートを配る

**最初に一度だけ**

1. GitHub のアカウントを作り、**2段階認証をオンにする**（乗っ取られると全員のPCに変なプログラムが配られてしまうため）
2. GitHub で新しいリポジトリを作る（Public でOK・中身は空でOK。例：`mimic`）
3. `app.py` の `UPDATE_REPO` を `"ユーザー名/mimic"` にする
4. この状態で `build.bat` を実行し、できたインストーラーを配る（`UPDATE_REPO` が入っていない版は自動更新されない）
5. （任意）[GitHub CLI](https://cli.github.com/) を入れて、ターミナルで `gh auth login` しておくと、公開まで自動になる

**バグを直すたび**

1. このフォルダでプログラムを直し、`start.bat` で動作を確認
2. `version.txt` の数字を上げる（例：`1.1.0` → `1.1.1`）
3. `installer` フォルダの `release.bat` をダブルクリック → 更新内容をひとこと入力
   - GitHub CLI があれば自動で公開される。なければブラウザが開くので、表示どおりに zip をドラッグして「Publish release」
4. みんなのアプリは、次に起動したときに自動で更新される

- GitHub に上がるのはプログラムだけ（資料・記憶・APIキーは入らない）
- ライブラリを増やした（`requirements.txt` を変えた）ときも、自動で入る
- Python 本体を入れ替えるような大きな変更は、インストーラーを作り直して配る
- `app.py` の `AUTO_UPDATE = False` にすると、自動では更新せず「今すぐ更新」ボタンのお知らせだけ出す
- 部を引退するときは、GitHub のリポジトリを後輩に移す（リポジトリの Settings → Transfer）

### 注意

- 資料や記憶はPCごとに別々。あるPCで追加した資料は、ほかのPCには自動で入らない（インストーラーを作り直して配る）
- 無料枠では、送った内容が Google のAI改善に使われることがある。連絡先・口座など個人情報は資料に入れない
- 「モデルが見つからない」と出たら、AI Studio で使えるモデル名を確認して `app.py` / `convert.py` の `MODEL` を書き換える
- 500 や 429 が続くときは、資料が多すぎる可能性がある → 検索型（RAG）への作り替えどき
- うまく起動しないときは、インストール先（`%LOCALAPPDATA%\Programs\MIMIC`）の `launcher.log` を見る

### 開発用の起動（インストールせずに動かす）

このフォルダで `pip install -r requirements.txt` のあと、`start.bat` をダブルクリック。

### 管理を引き継ぐ人へ

APIキーは人ごとに作る（前任者のキーは前任者が削除する）。
